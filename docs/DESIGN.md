# 设计说明（环线辑）

读者是要改这套代码的人。这里只写"看文件看不出来"的那部分：为什么这么切层、几条不
显然的口径、以及踩过的坑。逐条接口定义在
[`js/puzzles/CONTRACT.md`](../js/puzzles/CONTRACT.md)。

这个仓是 [纸上逻辑 Nikoli](https://github.com/z-biz-game/z-biz-game-nikoli-cos) 的
姊妹辑：外壳、存档、星级口径、无头复验套路完全一样，只有坐标系不一样。**不要把
四款里任何一款挪回格坐标**——珍珠与箭头的线走的是格心，圈环的线走的是格边，两者
共用一块画布才有意义；把它们塞进格坐标那套，等于逼玩家用整块棋盘去猜半格的方位。

## 一条主线：可复现

`generate(seed, sizeKey)` 是纯函数，`spec` 能 `JSON.stringify`，引擎不读时钟、不采样
未播种的随机数、不碰 DOM。这条约束换来三件实打实的东西：

1. 每日挑战不需要服务器 —— 同一天在所有设备上是同一套四道题（`registry.js` 的
   `dailySpec(day)` 是唯一的排题处，首页和路由两条入口都得走它）。
2. 求解器可以当测试用 —— 单测里"40 个 seed 每档都数得出唯一解"之所以稳定，是因为
   双方拿到的是同一道题，而不是各自摇了一次。
3. 存档只需要存记号，不需要存答案。

引擎里出现的 `now` 只服务动画与庆祝帧，一律由外壳传进来，不参与任何判定；判胜一律
看盘面本身（`环是否闭合`、`数字是否全凑够`）。

## 一块画布服务两种坐标族：半格索引

相邻两个点之间是一次步进，称为"半格"。落子坐标 `(hx, hy)` 的奇偶就是它的类型：
`(奇,奇)` 是格心，`(奇,偶)` 是横边，`(偶,奇)` 是竖边，`(偶,偶)` 是点。四款玩法共用
一套 `js/core/lattice.js` 与一个 `js/ui/lattice_view.js`，靠引擎自报两件事区分：

- 认哪一类目标（圈环只吃边，珍珠/箭头/数桥只吃格心，收到别的原样退回 `false`）；
- `engine.step`：键盘光标一次挪几个半格。边玩法逐边长，走 1；格心玩法的目标隔一个
  半格一个，走 2。`home()` 也按这个数给初值，否则开局按空格打在空白处。

代价是命中框只有半个格，所以 `sub = cell / 2` 这条换算在三个地方必须一模一样：
`lattice_view.halfAt()`、引擎自己的绘制、无头复验的像素算式。写错一处不会崩，只会
让玩家以为"引擎算错了"——所以复验脚本里那句 `(h + 0.5) * sub` 是照着 `halfAt()`
的 `floor` 取带反推出来的，不是随手写的。

## 唯一性是"推"出来的，不是"数"出来的

这是本辑最值钱的一条，也是把生成器从 12 秒/道压到几毫秒的原因。

`propagate()` 每步只钉"别无选择"的那条边：满了就封其余、缺的正好等于剩下的未知就
全画、一个点最多挂两条环边……**一条推到底的链本身就是唯一性的证明**，而它的成本是
一次盘面扫描。所以出题的闸门是 `logicSolve()`（把 `propagate` 跑到不动点并铺满全盘），
`countSolutions()` 降级成保险丝：推得完的盘，数解只展开 0 个节点，几微秒。

反过来，"数得出唯一但推不完"的盘也能发吗？技术上可以，代价是每删一条线索都要展开
一棵回溯树。箭头 8×8 实测一道题 12.3 秒，手机上不可接受；改成只收纯逻辑盘之后同一
档 6 毫秒。珍珠 10×10 的下场记在 `masyu.js` 的档位表旁边：那一档满珠形状有 9/10
是真二义（中位数 65 个节点就能数出第二解），所以宁可不发那一档，也不发一道弱题。

## 0 是正经证词

圈环的题面里可以印 0。直觉上"这格周围一条边都没有"是废线索，但删光 0 之后会出现
一件麻烦事：**全盘没有强制的第一手**，`propagate` 一步也推不动，于是纯逻辑闸门把所有
题都拒了。0 与 3 一样是信息，只有 4 是白给的答案（那格四周全画满，圈环里不可能）。

## 兜底路径必须自己可验

`rescue()`（圈环的外边界一整圈）与 `fallbackSpec()`（箭头/数桥的人工盘）是"交不出题
就是违约"的产物。它们的价值不在跑得快，而在**被逐项验死**：`test/slitherlink.test.mjs`
在 4..10 每一档上都断言保底题面数得出唯一解、`validate` 通过、`par` 与笔画序列自洽。
另一条用例反过来守着质量下限——正常种子用不到保底（每档 12 道题里 `clues.length === n*n`
的题面数为 0）。保底不该被走到，但走到时必须交得出。

## 输入路径是单测的盲区

数桥曾经有一个跑完全部单测也发现不了的缺陷：`geomOf()` 的方向索引表在算"这座岛往某
个方向拖是哪条道"时，横竖都只比了 x。竖道两端 x 相同，于是 `dirs[p].v1` 永远是 -1，
从编号小那座岛出发的拖拽被静默丢弃——**一半的桥只有一头能搭**。引擎单测照样全绿，
因为它按 `spec.bridges` 逐根调用 `down/move/up`，两端的岛名对调一下就成了。

只有真指针事件 + 真视图能暴露它：`tools/playtest.mjs` 从题面里读出获胜笔画，换算成
像素，用 CDP 的 `Input.dispatchMouseEvent` 一路画到结算屏，并且两款坐标族各自跑一遍
键盘与副笔。这类"引擎没错、输入路径断了"的缺陷，是这条复验存在的唯一理由。

## moves 与 par：撤销不退款

一条边（圈环）/ 环上的一个格（珍珠、箭头）/ 一根桥（数桥）= 一次落子。擦掉重画、
撤销都不退款，所以 `moves - par` 就是玩家浪费掉的笔数，评星才测得出"在试错"而不是
"在倒带"。`par` 一律取唯一解的量（环的边数、环上的格数、桥的根数），这是可证的下界：
谁也不能一次落子画出两条边。

实现上这条只依赖一件事：`snap()` 里绝不带 `moves`。三款格心玩法的快照一度都带了它，
于是 `back()` 顺手把步数也倒回去了——单测要钉不住，界面上就是一颗永远拿不满的三星。

## 分层

```
js/main.js             装配 + window.nikoli（无头复验的唯一入口）
js/ui/app.js           路由、计时、记分、评星、键盘 —— 设备无关的输入在这层收敛
js/ui/lattice_view.js  半格坐标 ↔ 画布像素的唯一换算处；指针事件 → 整数半格
js/puzzles/*.js        每道玩法一个文件：题面、状态机、求解器、渲染
js/puzzles/registry.js 外壳需要知道、引擎不该关心的那部分（图标、副笔的语义、每日排题）
js/core/               rng / storage / audio / paper / theme / lattice
```

引擎只准 import `js/core/*`，绝不 import `js/ui/*`——否则 `node --test` 跑不动，
求解器也就当不了测试用。这条用 grep 钉在每款玩法的单测里。

## 与姊妹仓的存档隔离

两个仓都往 `localStorage` 写每日完成记录。键前缀一个是 `nikoli-daily|`，一个是
`loops-daily|`，写串了会出现"在对面打过卡，这边首页却已经划掉"。前缀集中在
`registry.js` 的 `dailySeed()` 一处，改那边不用改这边。
